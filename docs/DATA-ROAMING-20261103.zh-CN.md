# 数据漫游与看板 AT 通道

## 权限与实际状态分开

网络锁定页增加「数据漫游」，使用与 VoLTE、频段锁定相同的直接子级
`mud-sec > h3`，不是独立大标题。按查看的逻辑 SIM 保存
`unisoc_modem.main.allow_roaming0/1`，缺省与新配置均为 `0`。
开启后仍以基带注册状态为准，不会把本地网络变成漫游。
APN 的 `roaming=IP/IPV4V6` 仍表示漫游 IP 协议，不是权限。

没有引入未经确认的厂商「漫游 AT」。权限属于数据策略：在现有
`mobile-data` 激活 PDP 前检查；漫游被禁止返回独立退出码 8，
netifd 显示 `ROAMING_DISABLED` 并保留 autostart。现有
`mu300-network-recovery` 订阅注册和权限变更事件，停止受限制的
数据连接，或在允许漫游／回到本地网络后恢复；不关闭 RF、IMS、
通话或短信，不新增轮询服务，不覆盖手动断网和射频关闭。

保留 CEREG 与 C5GREG 两个被动状态，注册的 NR 优先于 EPS；
未注册的域不能遮掉另一域。查询仍通过唯一 AT owner 和
`AT+SPACTCARD=0/1;...`。组合查询被 CP 拒绝时，按现有采集器的
方式分别读取缺失字段，不增加固定等待。CP 重启、移卡及关 RF
清掉相应旧注册记录，避免另一张卡或旧 NR 状态影响权限。

## U30 Pro 的 nr6 / nr7

实机为 `/etc/mu300/platform=u30pro`、Linux `6.12.94-u30pro-p1`。
检查确认 `/dev/stty_nr6`、`/dev/stty_nr7` 存在且当时无人占用。
这两路此前没有加入 `modemd_single_layout`，看板预留池最终退到
通用 nr2，与完整采集和其他命令竞争。

现在由同一个持久 C bridge 统一持有 nr6/nr7，用户态 modemd 增加
atd6/atd7，`reopen=0`。两个逻辑 SIM 都通过显式 SPACTCARD 使用这
两路，不能用通道号推断卡槽；不把 nr6/nr7 的无上下文 URC 归给 SIM。
不变更 nr0/nr2、nr3/nr5 的现有拨号、短信所有权。

实测 nr6、nr7 分别执行 SIM1/SIM2 的 `SPACTCARD;CFUN?` 均返回
有效 CFUN 和 OK；未改变射频状态。4 路并发实时读取全部成功。
同 SIM 只共享尚未结束的一轮读取，不以旧缓存冒充新结果；单通道
布局等现有采集结束后调度，双通道布局保留并行能力。只使用事件
及有限请求超时，没有新增常驻定时轮询。

通道锁被占用或已打开但尚处初始化 drain 阶段时，报告忙碌；真正
无应答仍保留错误。前端成功信号清除更旧的元数据错误，较新的
错误不会被旧信号覆盖；失败时清理旧 dBm/RSRQ/SINR，技术错误
不再占用网络制式标题。

## 验证与边界

- U30 Pro 实机热部署，未重启整机、基带或 C bridge，WAN、屏幕、
  触摸保持正常。实际 HTTP ubus 验证读写与 ACL，读取保存值，并
  保留测试前用户选择。未写 NV、IMEI、GPT 或启动分区。
- 82 项漫游/恢复策略断言、36 项既有恢复/SIM 断言、11 项请求
  调度断言、34 项原生通道断言通过。目标 UCI 测试使用合成注册
  和事件传输替身；真实 ubus 另在实机验证，不能混为一谈。
- 18 组中文/英语/土耳其语、明暗主题、320/390/1280 宽度布局
  覆盖开关、加载、重复点击、错误、只读权限及同款标题样式。
- `tools/test-u30pro-root.py` 比较生产源与既有准备根，验证新增
  helper/module 的构建收录和目标 ucode。没有重新编译内核。
- 本机当前注册为 home。真实漫游网络下的运营商行为没有实测；
  关闭/恢复策略的边界由离线事件测试验证，不能称为漫游实测通过。
