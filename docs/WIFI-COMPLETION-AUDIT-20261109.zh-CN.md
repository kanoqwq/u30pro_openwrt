# Pro Wi-Fi 完成回收核查

针对 MU300 U30 Air PCIe 发送回收故障，核查本仓库实际使用的 AIC8800
SDIO 路径。U30 Pro 与 F50 Pro 共用该驱动；继承目录中的 SC2355 PCIe
源码不是两款 Pro 的生产 Wi-Fi 驱动，不能据其相似文件名认定受到影响。

现有 `aicwf_txpipe_thread()` 在同步 SDIO 写入成功返回后，才推进 write
索引、减少占用计数并唤醒生产者；写入期间缓冲仍归 writer 所有。
固件额度查询会先排空已提交的数据，保留命令顺序。没有 MU300 中“提前
归还完成额度，再分配一个可能失败的回收工作项”的同一流程。

重新执行 `tests/u30pro_sdio_pipeline.py` 14 项及
`tests/u30pro_sdio_recovery.py` 4 项，全部通过。覆盖顺序与缓冲归属、
分配／线程创建失败、满队列、退出、超时、I/O 错误不重放、实际生产者
额度顺序和 SDIO 恢复。本轮没有发现需要移植 MU300/E5 修正的同类缺陷，
因此未修改 AIC 驱动，不因其他平台的日志增加重置、轮询或禁休眠。

上述为源码核查和离线回归，不等于证明 Pro 不可能断流。若 Pro 实机
仍出现热点可连但数据不通，需要其实际固件版本和当时的 AIC／MMC 状态。
