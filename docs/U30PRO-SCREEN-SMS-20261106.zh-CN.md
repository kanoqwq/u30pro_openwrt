# U30 Pro 屏幕短信交互修复

## 范围

只修改 Pro 原生屏幕程序和 `u30pro-ui-feed`，不改变 MU300 的 AT／短信守护程序、
NR0 接收入口、消息池或 SIM／IMEI 映射。F50 Pro 不启动屏幕服务。
没有进行新的实机部署、短信发送或用户消息修改；设备已被用户拔走。

## 行为

- 日期和可选未读信封按整体宽度居中；没有未读时日期单独居中。等待授时时
  使用同样布局。信封不再放在电池／充电区域，充电不隐藏未读提示。
- 打开详情捕获短信 ID、逻辑 SIM 和列表位置。新短信改变列表顺序时，详情仍
  对应原来的消息；换 SIM 不会把另一张卡同 ID 的内容塞进已打开的详情。
- 屏幕通过 `u30pro.panel.request` 的 `sms_read {id,slot}` 扩展事件请求读取，
  feeder 调用既有 `mu300dash.sms_show`，由原消息池实现标记已读。不直接操作
  AT、不自行重写消息文件。后端确认后重新读取列表及未读计数；失败不假装已读。
- 详情保留一份已打开的正文，周期状态刷新不会把它降回预览。去掉 CLI 输出
  的元信息头，仅展示正文；关闭详情时释放该状态。队列按卡／ID 去重，最多
  16 个请求，不积累历史或磁盘缓存。
- 返回按钮、水平滑动、物理按键及长按空白处都先退出详情，回到原短信列表
  位置，不先关闭底层列表。既有页面滑动、QR、PIN 和电源菜单语义保留。

## 接口兼容

原四列 `sms.N=peer<TAB>time<TAB>unread<TAB>text` 不变，增加可选的 `sms_id.N`
和 `sms_slot`。旧 `sms_ack` 批量确认请求仍由 feeder 接受；原生详情改用明确的
`sms_read {id,slot}`，关闭时发送 `sms_close`。新原生程序每帧清除旧 ID，缺少
可用 ID 时要求刷新，不猜测读哪一条消息。现有 ubus 对象及方法没有删除。

## 验证

`tests/u30pro_screen_sms.py` 编译实际 UI_HOST 原生程序并运行五个场景，同时
用现有 ARM64 ucode 执行生产 feeder 的真实函数和事件回调：

- 日期单独居中的实际像素对照；充电＋未读的图标位置与点击区域。
- 稳定卡／ID 确认、列表重排和不同 SIM 相同 ID 的隔离。
- 详情的手势、按键和返回按钮路径，以及列表滚动位置。
- 后端操作后计数、最后一条未读清除、失败／重试、不重复确认、正文不退回
  预览、关闭释放、无效请求、旧事件和有界队列。
