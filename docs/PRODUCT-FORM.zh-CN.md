# SIM 产品形态覆盖

适配设置中的「产品形态」为 SIM 卡源拓扑提供型号内的手动选择，默认跟随
原机 `board_id`。它不改写原机板号、产品型号、GPIO 接线表或 IMEI。

入口位于「适配设置 → 平台适配 → 产品形态」，嵌入现有表单而非独立的顶部
卡片。仅 U30 Pro、F50 Pro、V50 显示；已识别为 Pro 但产品标识读取失败时
显示可重试错误，不再误当作“不支持”隐藏入口。普通表单保存不改写形态，
须使用形态控件自己的保存按钮确认。

## 支持范围

| 产品 | 已实现的形态编号 | 含义 |
| --- | --- | --- |
| U30 Pro / MU5358 | 0–6 | 使用 `u30pro-card.sh`，包含两种不同的二贴组合 |
| F50 Pro / MU3356 | 0–5 | 使用 `f50pro-card.sh`，包含两种二贴、二贴二插及双插 |
| V50 | 0–3 | 使用 V50 B15 的 `v50-card.sh`，编号不套用 Pro |

相同贴／插数量可能有不同的内置卡位置，界面同时展示内置卡编号。
MU3356 的测试板号 1000 仍不自动推定其切卡接线。原机板号未知时，用户可以
明确选择本型号已实现的形态；恢复自动识别仍以原机板号为准。

## 生效与保留

三个产品分别保存 `unisoc_modem.main.u30pro_board_override`、
`f50pro_board_override`、`v50_board_override`，不会相互套用。
「恢复自动识别」删除本型号覆盖项，不修改原机板号。

`/usr/libexec/unisoc-modem/product-form boot` 在 CP 启动前发布本次开机的
只读形态选择到 `/run/mu300-product-form-<model>`。卡源库优先读取该记录，
因此网页保存不会重新解释正在运行的基带，也不会即时切 GPIO、切数据卡或发 AT。
重启后的启动路径才更新有效形态；服务重启不会替换运行中的选择。

启动准备会删除新形态中不存在的旧上网卡源选择；F50 Pro、V50 不完整或不再适用的
卡源配对会成对清理，避免半套配对导致 CP 启动失败。有效选择保持不变。
U30 Pro 单插形态只有逻辑栈 0，原先指向栈 1 的默认上网卡会归到栈 0。
短信、流量账本、APN、IMEI、NV 和显式射频权限不会被此功能改写。

## 接线与回归

Pro 的原生 vendor 服务在 `u30pro-sim-preinit` 之前执行准备；MU300 的
vendor 服务仅为 V50 调用此入口，F50、U30 Air 的启动路径保持原实现。
完整 rootfs 安装、发布关键文件清单和 RPC ACL 均收录新文件。

### 旧系统差异升级的产品标识恢复

2026-11-10 U30 Pro 实机：升级记录与当前 release 的 profile 都为 u30pro，
原生 SIM 控制器为 mu5358，但旧安装缺少 `/etc/mu300/model`。本次完整包
包含该文件；差异包只含变化文件，两版内容相同，因而未重建现场缺失文件。
卡板准备返回 product_form_unsupported，vendor 服务在启动 CP 之前退出，
随后表现为 AT 无应答。不是据此判定基带崩溃，也未发现刷入 F50 Pro 包的证据。

vendor 现在先执行 `u30pro-product-identity --restore`，现存有效标识保持原样，
不为正常启动追加 release 或 SIM 布局要求，也保留指向有效标识的自定义符号链接。
只有文件缺失、需要重建时，才核对当前 release 的产品、原生平台和 SIM 布局，
三者一致后原子恢复。U30 Pro 必须对应 mu5358，F50 Pro 必须对应 mu3356；
重建证据不完整或冲突时报错，不覆盖、不猜型号，不改卡源或发送 AT。
只读检查使用 `--check`。该入口随产品 overlay 进入两款正式包，不需要
修改 E5、MU300 的启动路径或安装器。十二项离线回归覆盖两产品、缺失标识、
配置保留、冲突拒绝、并发与服务顺序；新增启动迁移的实机重启仍待验证。
OTA 的校验、文件合并、插件及配置保留规则均不变；本修复不增加系统原样校验，
也不要求用户撤销本地小修改。MU300 的 V50 由实际机型探测选择卡板库，不依赖
Pro 产品标识；F50/U30 Air 和 E5 各型号的 vendor 启动没有这条新增依赖。

进一步只读调查发现，设备保留的 11 月 6 日 openwrt.old 同样缺少标识，且存在
多次完整更新备份。完整更新的 keep_list 用旧 etc/mu300 替换新目录，而
image_own_save/restore 原先只恢复版本与包清单，未保留新镜像的 model；用真实
函数离线复现了“新包有 model，保留旧配置后 model 消失”。目前无法精确确定
最早发生在哪一次更新，不能说本次差异补丁删除了它。

现有完整更新库和 Android 保配置安装入口均补充只在缺失时引入镜像 model，
现存文件、用户自定义符号链接及其他设置不覆盖，也不增加 OTA 校验。MU300
共用入口同步该修复；不带 model 的普通 MU300 镜像保持原行为。

本机经授权仅补回完整包中的 7 字节 u30pro 标识，并启动原 vendor 服务，
未部署新脚本或重启。AT 返回 OK，原连接流程获得 IPv4/IPv6；UCI 配置摘要、
卡源 GPIO 与服务脚本摘要均未变化，NV 通知服务保持 writeback=off。该实测验证
本次故障的标识缺失因果关系，尚未验证新启动迁移或完整更新的实机重启。

`tests/test_product_form.py` 使用真实卡源库、隔离 UCI 存储和模拟进程状态，
覆盖型号隔离、自动／手动／恢复、重启生效、无效选择清理及保存失败。
`tests/product_form_browser.py` 覆盖三个产品、中英土三语、深浅主题和四种
屏幕宽度，以及只读权限、取消确认和保存失败。本功能尚未做实机重启验收。
