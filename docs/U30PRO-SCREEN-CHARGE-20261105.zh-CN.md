# U30 Pro 屏幕直供电开关回弹修复

## 确认的源码问题

屏幕原先从充电器 `charge_behaviour` 的 `inhibit-charge` 判断直供电开关。
同一个硬件停充状态也用于自动充电上限；网页则以公共充电策略的 `paused`
（手动暂停）为准。因此关闭手动直供电后，上限策略仍停充时，屏幕会重新显示开启。
此外，旧屏幕在后台动作完成前就提示成功，没有处理后端返回的 `ok:false`。
这能解释本次反馈，但未对反馈者的实机进行复现。

## 修改及边界

- 屏幕通过既有 `mu300-charge.get` 获取手动暂停、上限和待恢复状态。
  硬件采集继续读取电流、电压和在线状态，不再覆盖手动开关。
- 关闭直供电只执行公共 `resume`，保留充电上限；达到上限时单独显示
  “已按上限暂停充电”，OTG 等待恢复时单独显示等待状态。
- 控制脚本检查结构化结果，通过新增的 `u30pro.panel.charge_result`
  回执通知屏幕；请求编号隔离过期回执，忙时不重复提交。
  成功后才更新开关并提示成功，失败或通信超时明确提示。
- 不更改驱动、充电阈值、限流、温控或 OTG 供电规则，不修改 NV。
  原有屏幕/插件 API 保留；F50 Pro 不启用屏幕和电池控制服务。
- 正式源路径为 `devices/u30pro/overlay/usr/sbin/u30pro-ui-feed`、
  `u30pro-panel-control` 和 `devices/u30pro/native/tools/`。
  通过既有 runtime builder 及 sources/finish 收录，不使用实机文件作构建输入。

## 离线验证

`tests/u30pro_screen_charge.py` 执行真实原生 UI 和真实控制脚本，覆盖手动停充、
上限停充、关闭后多轮硬件采集、网页状态同步、重复点击、后端忙/应用失败、
超时及过期回执。`tests/test_charge_control.py` 在隔离 OpenWrt 容器运行真实
公共策略，增加 U30 Pro 原生充电器的上限及 OTG 恢复用例。
同时检查电源菜单、插拔亮屏、翻页和网页充电管理，并编译 ARM64 原生屏幕程序。
这些检查不等于实机验收；本次未部署设备，也未改写已交付的发布包。
