# Pro 系列 SDIO 调谐与错误恢复

来源：[33333s/U30pro-openwrt 08bda84b](https://github.com/33333s/U30pro-openwrt/commit/08bda84b05889068490655f8e93d6aa649aba95e)。
适用本仓库共用 UMS9632 / AIC8800 内核的 U30 Pro、F50 Pro；不改产品配置、
SIM 拓扑、基带、CPU 策略、安装布局或现有实际 204.8 MHz 时钟。

## 收录内容

- 记录 SDR104 DLL 有效窗口、选中相位、温度及重新调谐原因。窗口不足 60% 时
  提示诊断信息，不自动降频。BSP 和 WLAN 驱动完成各自 F0 配置后请求重新调谐，
  避免继续使用配置改变前的窗口。
- 已有窗口可先双次检查内部三点，失败则完整扫描。分配失败、无有效采样点等
  情况恢复进入前的 DLL 配置、延迟和 DMA 标志，并返回错误。
- 保留完整的有限 DLL 扫描和 MMC 单次命令超时。`mmc_send_tuning()` 的
  150ms 是单次数据超时，不能作为厂商整轮扫描的截止时间；坏采样点本来就可能
  超时。不存在“所有调谐都能在 150ms 或 5 秒内完成”的保证。

## 与原提交的区别

温度检测由真实 SDIO 请求触发：有流量时最多每五秒提交一次工作，无流量不唤醒。
默认温差 10°C 或距上次调谐 30 分钟时标记待调谐，等请求间隙；持续繁忙最多
延后十秒再请求调谐。工作函数不自我排队，不新增常驻轮询线程或周期定时器。
热区读取不占用 MMC host 或调谐状态锁；最多读取十二次寻找相邻稳定样本，
没有稳定值则保留未知状态。非 SDR104、调谐关闭或主机休眠时不做温度检测。
挂起、探测失败及移除都会先禁止重新提交，再同步取消工作，避免释放后访问。

只对已确认无副作用的 flow-credit 寄存器 CMD52 读取做有限重试：最多四次，
超过既有发送等待期限不再开始新尝试；单次命令仍服从 MMC 自身超时。
临时关闭 CRC 自动调谐后恢复原状态，不永久修改全卡 CRC 策略。

CMD53 FIFO 读写可能已经消费部分数据，接口又不能可靠报告已消费前缀，
因此**不自动重放**。CRC 错误执行一次中止并请求调谐，原错误交还调用者；
超时不追加可能继续阻塞的中止命令。原有 TX 流水线错误锁存、所有权和退出
顺序保留，不能将其描述为所有传输错误均可自动恢复。

没有带入原作者的固定分区发布配置、故障注入 sysfs 或全局 CRC 禁用策略。

## 构建与离线验证

生产源码仍由既有 overlay、`tools/u30pro-build.py kernel` 和
`tools/u30pro-package.py sources/finish` 收录；原生源摘要及适配原因登记在
`devices/u30pro/adaptations.json`。没有引用临时工作目录或设备里的修补文件。

`tests/u30pro_sdio_recovery.py` 编译实际调谐函数及恢复头文件，通过 ASan/UBSan
验证完整扫描（包括总耗时超过 150ms 的正常扫描）、窗口变化、失败恢复、
不稳定温度、温差/时间触发、活动/空闲、挂起/移除并发、双主机隔离、
信用寄存器重试以及部分 FIFO 传输绝不重放。该测试已接入原生回归入口。
另运行发送流水线、真实时钟计算和移植检查，并重新编译匹配的 Image/模块。

后续经用户授权，已在 U30 Pro 更新匹配的 boot／模块并正常重启，实际时钟
204.8 MHz、有效调谐窗口 71/76、调谐失败零次，蜂窝和热点恢复正常。
记录见 [SIPA 现场与验证](PRO-SIPA-TX-FLOW-20261106.zh-CN.md)。这些检查没有
覆盖长时间温漂及吞吐压力，不宣称吞吐提升；F50 Pro 尚未做本轮硬件验收。
之前发布的固件 ZIP 不包含本轮改动，需要重新组包才能交付。
