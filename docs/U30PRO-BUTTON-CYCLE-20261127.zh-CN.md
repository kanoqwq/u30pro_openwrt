# U30 Pro 快捷键切卡策略

U30 Pro 已有网页卡源组合和快捷键列表切卡，之前漏接的是 F50 Pro 新增的
「当前两个 IMEI 卡源来回切／全部卡源列表循环」选项，本次补齐同一共享算法。

- 网页：设备管理 → 实体按键 → 快捷键切卡方式。默认 `pair`，读取现有物理卡
  owner 的实时 `logical_cards`，在 IMEI1、IMEI2 已选卡源间双向切换，不改两路选择。
- 可选 `list` 保持 U30 Pro 原来的原生 ID 升序，与其 SIM 页面一致；F50 Pro 的
  外置1 ID4、外置2 ID3 特殊顺序不变。两机型的板型表不混用。
- U30 Pro 设置保存在 `u30pro_native_control.settings.home_button_cycle`，与其原有
  按键设置同一 UCI 包提交。缺省为 `pair`，保留原按键动作、射频权限和用户数据。
  旧网页发送空的隐藏 `cycle` 字段时视为未修改，不能把新策略清空。
- 单源板型只允许在确有一个有效实时卡源、另一栈为 null 时不切换；多源板型的
  卡源缺失／未知仍报错，不按保存值猜测或降级成列表循环。
- 仍使用原生屏幕按键入口 → 既有按钮分发 → ucode 策略 → 原有 data-sim apply。
  不增加轮询、AT 读者或新的射频流程，单击和电源长按不变。
- F50 Pro 原有 LED 反馈不变；U30 Pro 仅显示简短策略说明，不声称具备同样的 RGB 灯。

共享 ucode、按钮分发和网页已在既有 sources/finish 路径交付，完整包、普通更新和
差分更新共用这些文件；无需重新编译内核或安装器。

## 独立卡源组合

U30 Pro 的 SIM 管理页也加入 IMEI1／IMEI2 两路卡源选择。范围来自本机物理卡
owner：IMEI1 是内置1／外置1，IMEI2 是内置2／内置3，按实际板型过滤。单源形态
没有组合框。U30 Pro 使用自己的 0..3 编号，不套用 F50 Pro 外置双卡的 ID4。

新事务用 ucode 实现，薄 shell 入口仅持有现有 SIM 控制锁／切卡门闩和 eUICC
保护。低层 GPIO、SFUN、实时工作模式准备、RF 权限、锁频重放仍交给原 mobile-data
和物理切卡 owner。只在当前数据栈的卡源改变时中断／恢复 WAN；修改另一栈不会
重拨当前数据卡。不会改变 data_sim、双待和射频保存值。

两路选择以 `unisoc_modem.main.u30pro_route0/1` 保存，在 CP 启动前一起验证后
恢复。后续列表切卡会同步两路保存值，失败恢复原值；产品形态改变时由现有
product-form 启动迁移清理不再适用的卡源组合，保留短信、APN、流量与其他设置。
失败回退两路卡源及 WAN 原意；如果回退失败保留故障标记，不伪报成功。

## 六轮离线验证

1. 实际 ARM64 ucode：两款 Pro 的形态、混搭双向切换、单源和错误状态。
2. 原按钮分发经过实际 ucode，再交给原 apply；列表与旧行为比较，pair 不改源。
3. 配置保存／旧客户端／失败恢复，以及连续 40,000 次实时目标选择，中途改变卡源。
4. 实际 uhttpd → rpcd → UCI：四机型读写、换会话、权限与错误值拒绝。
5. 实际差分生成／应用／撤销和两轮普通更新，保留两款 Pro 策略、卡源与插件数据。
6. 中英土、手机／桌面浏览器：显示、默认、保存、故障恢复与只读，其他机型隐藏。

六轮均已通过：基础设置／形态迁移 45 项、目标 ucode 选择 5 项、目标组合事务 7 项、
原物理卡／数据卡／更新保留 68 项、原灯控 6 项和实际按键分发 2 项，以及四机型
三语言手机／桌面浏览器、真实 HTTP/rpcd 读写／权限和 40,000 次连续选择。
宿主未运行的两项目标 ucode 测试由目标 ARM64 分发测试补齐。
