# Pro 系列 AIC8800 SDIO 发送流水线

参考：[33333s/U30pro-openwrt ff4f4906](https://github.com/33333s/U30pro-openwrt/commit/ff4f4906e755b7e9286c2963d9f27e11b2dadccb)。
本次仅吸收发送流水线、缓冲保护和诊断计数的思路，重新处理并发与退出；
不直接合入原提交的 CPU 提频、固定核心亲和性、时钟修改或发布配置。

## 适用范围

U30 Pro / MU5358、F50 Pro / MU3356 共用的 UMS9632 / AIC8800 SDIO 驱动。
不修改 E5、MU300 仓库，不把该实现用于 SC2355，也不改变两款产品的卡源、
屏幕、电池、固件加载、NR0 事件入口和 AT 控制所有权。

原有真实 204.8 MHz 配置保持不变，不调整共享 PLL，不新增 CPU 频率投票、
调度优先级或绑核，不改变用户调频、核心开关和温控设置。

## 发送与内存所有权

- 每台 SDIO 设备独立建队列，复用已有 BSP 预留池，再分配两个同容量缓冲。
  本机池容量为 51,200 字节，额外数据存储约 100 KiB，不复制第二份完整驱动。
- 原发送线程继续整理聚合包；一个写线程按 FIFO 执行 CMD53。最多两个缓冲
  在排队或写入，第三个留给生产者，不在写入完成前修改或复用其内容。
- 查询固件可用缓冲、发送命令和离开发送处理时，等待此前交接的数据完成，
  保留原来的命令顺序与固件额度扣减规则。
- 聚合参数只接受 3–32；运行时调低参数用 `>=` 判断已达到上限，避免漏掉
  原来只判断相等的刷新时机。每次复制还单独检查实际池容量、描述符、
  对齐、链尾和最终 512 字节传输补齐，不能只依赖“每包小于 1600 字节”。
- 容量先满时先发送已有聚合并重新取得额度，再重试当前帧；不能容纳的帧
  显式丢弃并计数，不越界、不破坏此前已经整理好的数据。
- 最后一块传输补齐区域清零，避免把旧缓冲内容作为尾部发送。

## 错误、休眠与退出

`tx_pipeline` 默认启用，只允许在模块加载时选择；不允许运行中切换正在
被两个线程引用的缓冲，也不在分配/启动失败后悄悄切换后端。初始化失败
清理本次拥有的资源并报探测错误，保留原 BSP 池的所有权。

等待队列空间或排空沿用驱动现有的 `CMD_TX_TIMEOUT`（5 秒）上限，
只在实际需要等待时生效；空闲线程
阻塞在 wait queue，没有轮询或新的周期工作。首次错误保持到设备释放，
后续命令和额度查询返回错误，不重发无法确定是否已经到达固件的数据。
不新增自动复位或降速来遮盖故障。

退出先取消提交并唤醒等待者，再停止写线程，最后停止旧生产者/电源线程，
恢复预留池指针并释放额外内存。未完成的真实 SDIO 请求仍由 MMC 主机的
请求超时负责，不能为了让退出看起来更快而提前释放 DMA/传输引用的缓冲。
写线程可能因 I/O 失败先退出，因此单独持有 task 引用到 join 完成。

同时修正旧 AIC 总线的清理顺序：TX/RX/IRQ 线程均在无线平台对象释放前停止，
电源线程及其定时器也先停止。每个线程创建后立即检查错误，传播实际错误码，
不再在线程创建失败时返回初始值 0；清空已释放的平台/收发私有对象指针，
避免嵌套失败清理重复访问。

休眠判断包含已交接、尚未完成的聚合及正在整理的聚合；实际空闲后仍走
原电源管理，不禁用 Wi-Fi 休眠。

## 诊断与构建接入

只读统计：

```sh
cat /sys/module/aic8800_fdrv/parameters/tx_pipeline
cat /sys/module/aic8800_fdrv/parameters/sdio_stats
```

统计为模块本次加载以来的累计值，原子读取但不是整行同一时刻的快照：
`writes` 是 CMD53 写尝试数；`bytes` 仅累计成功写的字节；`write_us` 包含
取得 SDIO 主机的等待和写入；另有写错误、流控寄存器读取耗时/等待/错误、
聚合提交数/包数和边界丢弃数。聚合计数不是无线 ACK 成功数。

源码在正式 `devices/u30pro/native/kernel/ums9632/overlay/` 内；原导入文件
的当前摘要和适配原因登记在 `adaptations.json`，新增队列头文件随完整覆盖层
进入源码收据。原有 kernel builder 编译驱动，sources 组装步骤根据
`modules.order` 安装同次构建的模块；两款 Pro 共用这份驱动，不另开构建缓存。

## 验证边界

`tests/u30pro_sdio_pipeline.py` 已加入 `tools/test-u30pro-native.sh`。
它把实际队列头文件、聚合封装和生产者函数编译为 pthread/SDIO 模拟程序，
使用 AddressSanitizer / UndefinedBehaviorSanitizer 检查：
有序交接 5,000 次、缓冲占用、取消满队列、排队/排空超时、I/O 错误不重放、
分配和线程创建失败清理、双实例隔离、参数/字节边界、补齐清零及容量触发刷新。
另核对命令屏障、休眠和退出的生产接线。

这些是离线故障注入和编译验证；尚未在本轮部署设备。原作者记录的吞吐提升
混合了 CPU 提频等改动，不能当成本实现的实测收益，实际速度与功耗仍待硬件验收。
