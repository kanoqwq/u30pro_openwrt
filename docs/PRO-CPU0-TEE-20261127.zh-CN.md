# Pro 网页核心控制保留 CPU0

U30 Pro、F50 Pro 使用同一 `u30pro` 平台标记，CPU0 为 TEE 保留。

- 核心状态返回 CPU0 的 `required_online=true`，不再将其声明为可关闭；网页标注 `CPU 0 · TEE` 并禁用开关，附中英土说明。
- 后端在写入任何核心之前拒绝 CPU0 关闭请求，返回 `cpu_cores_tee`；修改网页 DOM 或直接调用 RPC 都不能通过该接口关闭它。
- 开机重放遇到旧的 CPU0-off 配置，会将 CPU0 恢复开启并修正该项，保留其他核心设置。重置旧默认快照也不会关闭 CPU0。
- 若恢复 CPU0 后其他核心写入或保存失败，原有事务恢复其他核心，CPU0 保持开启。其余平台仍按原内核热插拔能力工作。
- 沿用现有 ucode 控制器、RPC 锁和开机服务，不新增轮询、服务或内核修改；原有普通/差分 staging 已包含修改的后端、网页和翻译。

回归覆盖六组：普通平台的原 CPU0 能力行为；Pro 状态与伪造关闭请求；其他核心和临时/持久设置；旧配置开机修正且后续启动不重复改写；旧默认恢复与写入/保存失败恢复；中英土、手机/桌面的网页、DOM 篡改、错误恢复与重置。

实际 ARM64 ucode/只读文件故障夹具：`tests/cpu_cores_fixture.sh`，日志 `out/build-logs/20261126-164756-pro-cpu0-tee-runtime-95224/command.log`。真实 Chromium 页面回归：`tests/cpu_cores_browser.py`。两者通过；所有 CPU 节点为隔离文件，未操作实体 CPU、未热部署或重新打包。
