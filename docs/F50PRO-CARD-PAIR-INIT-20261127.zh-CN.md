# F50 Pro 卡源组合应用失败：射频开启前的模式准备

## 本机证据与边界

2026-11-27，MU3356 / board_id=4，用户运行
`f50pro-r20261126.170309-g3ec8289d-s05aff15c`。
基带自报 `MOCORTM_V2_24A_W25.15.1_P13.16_Debug` / `QogirN5_PS`，
编译时间 2026-03-20 12:01:42。没有按版本或摘要限制适用范围。

用户点击“应用卡源组合”，从原始卡源 `[3,4]` 改为 `[0,4]`：
IMEI1 从外置 SIM2 换成内置 SIM1，IMEI2 保留外置 SIM1。
只读进程采样记录了实际请求 `f50pro-card-pair apply 0 4`。
在本次启动 uptime 920.15 秒观察到目标栈 `SFUN=2`，921.67 秒为
早期回放的 `CAVIMS?`，921.89 秒进入 `AT+SPACTCARD=0;+SFUN=4`；
922.001 秒内核与原生监督器同时记录
`T_P_ATC ... mnphone_api.c line 7241` 断言，随后自动重载 CP。
任务最终返回 `physical_card_power_failed`、`sim_switch_failed_restored`。
程序已恢复原 `[3,4]` 与数据卡1；这次不是快捷键检测或网页提交失败。

采样和原始证据在忽略的 `work/f50pro-card-pair-20261127/`。
采样只读取进程、日志、既有状态和通过现有 owner 查询工作模式，未替用户
切卡、重启、刷写或修改设备程序。故障时的切卡由用户自行点击。

## 原厂对照与候选

本机已有 F50ProV1.0.0B22 的实际 `libimpl-ril.so`，SHA-256
`d0e9fca6cc92489d085fd9adfab75e7abe90986da754a1f1c4edc1849652384a`，
仅用于证据追溯。其 `processRadioPowerOn`（0x5a050）先调用
`initWorkMode`、`buildWorkModeCmd` 并发送模式命令，再进入射频开启；
模式构造器（0x57020）使用 `AT+SPTESTMODEM=...`，开启命令为 `SFUN=4`。
反汇编和字符串位置保存在同一调查目录。

现有换卡源控制器会关闭栈、关闭 SIM、切 GPIO、等待原厂五秒、SIM 上电、
等待 CPIN、回放设置，随后直接开启射频，没有这一模式初始化。
此前为空的栈还可能在冷启动时被存在性策略跳过；不能用整机的
`mu300-dual-radio-ready` 推断每个换入的卡源都已经完成模式准备。

候选只在 F50 Pro 的运行中换卡源路径、目标卡已有 CPIN 且用户允许该栈
射频时，查询当前 `SPTESTMODE?`，沿用既有双栈初始化器的模式对编码，
通过同一显式 SPACTCARD、同一 owner 发 `SPTESTMODEM`，再做原有回放和
`SFUN=4`。不发明默认网络模式，不更改默认数据卡、主栈选择或射频权限。
开机路线继续由原双栈初始化器负责；无变化卡源不新增 AT；V50/U30 Pro
不进入新增分支。原失败回退、未完成标记、WAN 用户意图保持。

这证明了原厂准备步骤的源码缺口以及实机断言出现的命令位置；候选能否
消除本机断言，必须再经实机验收，不能用离线模拟替代。
