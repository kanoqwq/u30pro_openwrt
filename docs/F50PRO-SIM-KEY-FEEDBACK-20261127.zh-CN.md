# F50 Pro 切卡快捷键的灯光反馈

## 行为

- 闪烁次数按当前切卡方式的列表序号，从 1 开始。双卡模式采用当前 IMEI1/IMEI2 卡源顺序；列表循环采用 SIM 管理的卡源顺序，外置1排在外置2之前。
- 目标为内置卡时绿闪，外置卡时白闪。切卡请求开始后先短暂熄灯，再闪相应次数；成功不重复闪，拒绝或失败改为红闪相同次数。
- 例如四项列表「内置1、内置2、外置1、外置2」，切外置1白闪3次；外置2未插卡导致拒绝则红闪4次。
- 短时反馈结束后重新读取当前信号状态恢复，Wi-Fi 灯继续正常更新。指示灯关闭或亮度为0的用户设置保持有效。
- 新的请求覆盖旧提示，迟到的旧请求结果不覆盖新提示；停止 LED 服务时取消提示并恢复正常状态。没有常态轮询、额外 AT 查询或独立灯控进程。
- 不改变既有卡源选择、拒绝条件、RF权限、AT owner、互斥锁和失败恢复，也不自动跳过空卡或改变用户保存的切卡方式。

## 实现与交付

新增 `f50pro-sim-key.uc` 使用实际卡源状态计算序号和颜色，再调用原有 `data-sim apply data`；现有 Python 分发器仅转交 F50 Pro 切卡动作，并保留具体失败文本供日志查看。

事件 `f50pro.sim-switch` 交给现有 `f50pro-leds` owner。`mu300.f50pro-feedback` 只管理一次提示的定时状态，仍通过原灯控的物理颜色、亮度和 break-before-make 实现写灯，未更改驱动。

新增 CLI、反馈模块和原 LED owner 都在 `devices/f50pro/overlay/`，由已登记的 `sources` 路径复制；选择器仍在共享 rootfs 源目录。沿用已启用的 LED 服务，无新增 rc.d 链接。普通更新和差分更新均携带镜像拥有的 `/usr` 文件；用户配置继续独立保存。发布根检查会逐文件核对机型 overlay。

网页下拉框下面的说明为「切卡按列表序号闪灯：内置绿、外置白，失败红。保存不切卡。」；中文、英文、土耳其文及 PO/LMO 一并更新。其他机型隐藏此项。

## 六轮离线回归

1. 实际 ARM64 ucode 选择器：各板号的当前双卡、混搭、全列表与外置编号；绿/白颜色和列表序号相符，单卡无动作及无效状态拒绝保持原样。
2. 反馈状态机：1～5次准确脉冲、立即拒绝红闪、重复/迟到结果、停止恢复，以及10000次连续请求，共83486项断言通过。该压力测试是纯状态机执行，不冒充10000次实际总线或实机切卡。
3. 实际 ucode worker → 私有 ubusd → 实际 LED owner：验证成功和拒绝时的事件、次数、颜色、原 apply 参数、真实子进程退出和具体错误文本。所有灯节点为隔离文件，原 AT/网络事务以记录型夹具代替。
4. 并发与生命周期：新请求覆盖旧请求、信号更新不打断脉冲且恢复最新状态、启动失败、终止原事务、停止 owner、关闭信号灯；原有启动动画、开机交接、Wi-Fi与配置更新的五组生命周期不变。
5. 实际普通更新首次/后续迁移，以及 Diff Studio/OTA 首次/第二次更新和撤销；携带所有新文件，保留卡源、切卡策略、按键命令、Wi-Fi和插件数据。
6. 四机型×中英土×手机/桌面共24组浏览器场景，简短说明、原保存和只读/错误行为；宿主按键22项测试中20项通过、2项目标端测试在 ARM64 环境另行补齐。
