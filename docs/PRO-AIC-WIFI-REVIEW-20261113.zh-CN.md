# Pro AIC8800 丢包反馈审阅与本机复现

日期：2026-11-13。结论为诊断记录，不代表驱动修复已合入。

## 群友反馈

审阅 `U30Pro-AIC8800-WiFi-debug-20261112.zip` 和用户提供的 `fix.patch`。
归档清单校验通过，并独立解析原始 pcap 与 CPE 的 AF_PACKET 捕获结果。
IPv6 UDP 下行、2 Mbps、1200 字节测试的唯一数据包集合如下：

| SDIO 聚合参数 | WAN / Wi-Fi 出口包数 | 客户端包数 | 缺失比例 |
| --- | ---: | ---: | ---: |
| 32 | 2124 | 1660 | 21.85% |
| 3 | 2099 | 2099 | 0% |
| 恢复 32 | 2098 | 1716 | 18.21% |

这组干预有力支持多包聚合或发送时序与问题有关，但不能确定具体缺陷分支。
Wi-Fi 出口 PACKET_OUTGOING 捕获不等于获得无线 ACK；SDIO 写调用成功也
不等于固件接受了所有子包。参数 3 在正常额度下接近单包提交，同时改变
批量及发送节奏，不宜直接作为永久降聚合的生产修复。

## 补丁审阅

补丁在审阅基线 `949ea8c` 上通过 `git apply --check`，未合入生产源码。
它主要涉及 IRQ/线程退出顺序、唤醒错误传播、额度重试、IPv4 TCP ACK
过滤、分配失败处理、软件头初始化和命令缓冲边界，存在可分项验证的修正。

当前不宜整包合入：

  提供该脚本，且替代了三个现有测试入口的直接调用。
- 引用的 `docs/PRO-AIC-WIFI-AUDIT-20261112.zh-CN.md` 未随补丁提供。
- IPv4 TCP ACK 改动不能直接解释上述 IPv6 UDP 丢包；补丁未改变数据多包
  聚合构帧算法或三缓冲实现，不能据此声称根因已经修复。

补丁内容一致性与可应用性检查不等于编译、回归或硬件验收通过。

## 本机授权复现

本机为 U30 Pro，发布提交 `0c99d86d`、指纹 `s686f53e9`，内核
`6.12.94-u30pro-p1`；手机为 PHB110。保持原有信道 36、HE80、2x2，
全程 `tx_aggr_counter=32`、`tx_pipeline=Y`。未刷内核、未应用反馈补丁。

| 测试 | 应用结果 | Wi-Fi 出口与手机捕获 |
| --- | --- | --- |
| 本机服务，IPv6 UDP 2 Mbps / 20 秒 | 0 丢包 | 4169 / 4169，逐包相同 |
| 本机服务，IPv6 TCP 单连接下行 / 15 秒 | 513.69 Mbps，68 次发送重传 | 未对 TCP 作逐包比较 |
| USB 转发，IPv6 UDP 100 Mbps / 15 秒 | 1.10% 应用丢包 | 156044 / 156044，逐包相同 |
| 同上，本次 iperf socket 缓冲设为 1 MiB | 0.0467% 应用丢包 | 156123 / 156123，逐包相同 |
| USB 转发，IPv6 UDP 2 Mbps / 30 秒，请求 100 ms 发送节奏 | 0 丢包 | 6251 / 6251，逐包相同 |

默认缓冲的 100 Mbps 复测中，手机 `Udp6RcvbufErrors` 增加 1563；为本轮
iperf 两端 socket 设置 1 MiB 缓冲后，该项增量为 0。未修改系统缓冲 sysctl。
两轮无线出口与手机包集合均完全一致，双方捕获内核丢弃均为 0。少量在无线
出口之前发生的缺失尚未定位，不把应用丢包全部归于无线或手机缓冲。

100 Mbps 测试实际使用了多包聚合，首轮统计增量平均约 15 包/次；并非暗中
关闭聚合。早期两轮转发抓包停止过快，尾部捕获环未完全排空，未将它们作为
完整窗口证据；后续停止前等待排空，并核对过滤、捕获及丢弃计数。

本机与当前手机组合未复现群友的严重无线缺包。USB 转发走同一 LAN bridge，
不等于真实 SIPA/WAN 路由、NAT 或软件卸载路径；也未覆盖不同客户端、信道
及长时间运行。因此不能据本机结果否定群友原始抓包或认定补丁有效。

诊断工具仅放在路由器和手机的专用临时目录。测试进程及临时文件已清理，
原始证据留在本地诊断目录，未提交用户抓包、设备地址或其他私人数据。
未重启设备、基带或热点，聚合参数最终仍为 32，无线持久配置未修改。
