# F50 Pro 双外置卡短信故障调查

## 实机确认

- 设备产品 `f50pro`，`board_id=4`，内核接线 `mu3356`。
- 已保存的两个卡源为 `[3,4]`，即逻辑栈 0 接外置 SIM2、逻辑栈 1 接外置 SIM1。
  用户确认：栈 0 的普通卡用于短信，栈 1 的物联网卡只上网。上网卡为栈 1，双待和两路射频均开启。
- 普通卡 CPIN、卡身份、SIM 文件元数据及 SMSP 记录可读，IMS 已注册；短信中心查询
  `CSCA?` 返回 CMS 313，SM 存储返回 CMS 310。不能据此推断实体卡损坏或未插入。
- 用户报告，重新初始化短信服务的瞬间曾收到一条，随后又不能正常接收。
  运行记录确认一条 NR0 `+CMT` 已保存到栈 0 短信池，未在报告中复制正文。
- CSMS/CMGF/CNMI 重设、SM/ME 存储重选、隔离后台 AT 查询、目标栈单独补发一次
  SFUN=4 后，短信中心查询仍返回 313。上述动作分别获用户授权；未发送测试短信。
  隔离后恢复后台操作，数据卡 WAN 保持 up，没有切数据卡、刷分区或修改 NV/IMEI。

## 参考与已排除的假设

对照 `33333s/U30pro-openwrt` 最新 `sms.uc` 与 `u30pro_atd.c`：上游通过原生串行 broker
原子执行 PDU 模式、存储选择和列表；这不是可直接替代本仓库双卡与 NR0 事件框架的实现。
保留本仓库的公共基带框架及每次请求的明确选卡，不启动第二个 tty owner。

本地 F50 Pro B22 `com.unisoc.hardware.rild.apex` 中 `libimpl-ril.so`：
SHA-256 `d0e9fca6cc92489d085fd9adfab75e7abe90986da754a1f1c4edc1849652384a`。
`testForIndication` 使用 CMGF=0、CSMS=1、CNMI=3,2,2,1,1；
`processSmsRequests` 的请求 37，成功参数 1 跳到 0x8bf78，发送 CNMA=1；失败发送 CNMA=2。
当前公共代码的正向 ACK 参数与此一致，未擅自改成无参数 CNMA。
该哈希只用于记录参考证据，不是固件白名单或运行时加载条件。
实机 CP 版本为 `5G_MODEM_V2_24A_W25.15.1_P13.16`，构建日期 2026-03-20，

## 待实机验证的启动顺序修正

内核按本机引导参数初始化 GPIO；原厂参数未带 psimswitch，因此 MU3356 分支使用
原厂默认电平 1。启动之后用户保存的双外置组合将 psim_select 改为 0；本次启动的
`f50pro-generation0` 也证实栈 0 发生了运行时卡源回放。原驱动日志打印了反向 psim 值，
不可将该日志值直接视为 F50 Pro 的 GPIO 初值。

新增 `f50pro-sim-preinit`，S13 `mu300-vendor` 在启动 CP 前调用：

- 使用已有 MU3356 board_id 卡板表，仅恢复明确保存的卡源。
- 完整验证两个来源及栈号后再写 GPIO，不发 AT、不改保存设置、不改默认卡源。
- 未保存选择、其他机型都不改变原厂 GPIO；已启动 CP／已存在 AT bridge 时拒绝重新改线。
- 原运行时切卡与射频互斥流程保留。修正已收录正式 sources/finish，而非只改设备。

离线卡板回归与新增启动前验证／存活 owner 拒绝检查通过。候选修正与短信故障的因果关系，
仍须部署后重启并重新收发确认；不能把离线通过称为短信修复成功。

## 授权部署后的结果

用户随后授权热部署两个脚本并正常重启，不刷 boot、不改 NV。新启动记录
`/run/f50pro-sim-preinit` 为 `0:1 -> 0:0`，且不再生成启动后栈 0 卡源切换的
`f50pro-generation0`。这确认 GPIO 在 CP 开始前已经恢复到用户的双外置选择。
普通卡 `CSCA?` 恢复正常，SM 存储可查询（当时 22/50）；两路 direct 接收配置标记均建立。
两份原选卡／双待配置的 SHA-256 前后相同，物联网数据卡仍使用 sipa_eth8。
期间网络释放一次 PDP，现有 NR0 事件恢复逻辑约两秒后重新连通，没有为此改动拨号逻辑。
后续实际短信收发与持续性验证单独记录，不把单次接口正常等同于完整验收。

用户随后确认：发送及间隔约半分钟的两次接收均正常。设备的发送任务也返回 `ok:1`，
普通卡短信中心继续可读，未见 direct ACK/import 失败。此次收发实机验收通过。
没有把这项 MU3356 开机顺序修正直接扩散到其他机型；共用 vendor 服务仅在产品为
`f50pro` 时调用新增 helper 和记录 CP 启动标记，U30 Pro 不执行该分支。

F50 Pro 的行为保持不变，诊断记录仍为 `/run/f50pro-sim-preinit`。
