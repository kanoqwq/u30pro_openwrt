# F50 Pro 漫游卡片初始化误判切卡

## 原因及只读现场

F50 Pro 的当前数据逻辑栈为 1，网页默认自动跟随上网卡。后端
`unisoc-roaming.get` 两个逻辑栈均返回 `ok=1`、各自 slot 正确、enabled=0；
这不是漫游配置或物理卡源异常。

`roaming.js` 曾在挂载时同步读取 `M.selectedSlot()` 并永久保存到 const。
此时异步 `sim_get` 尚未返回，自动模式仅有用于显示的临时 SIM1 默认值。
等公共模块解析实际数据卡为逻辑栈 1 后，卡片仍持有逻辑栈 0：初次响应被丢弃，
之后刷新／保存均误报“查看卡槽已改变”。没有因此成功写入另一卡。

## 修复

- 公共模块提供 `resolveSelectedSlot()`：自动跟随先等待既有的只读、无 AT
  `sim_get`，并复用在途请求；无法可靠解析上网卡时失败，不猜测 SIM1。
- 漫游卡片在解析完成后绑定读取目标。刷新允许重新绑定当前查看卡；保存仍须
  匹配已经展示的那张卡，真正切卡时清除旧状态并阻止发送。
- 读取或保存响应返回时再次确认查看卡，丢弃过期响应，不能把旧卡结果画到新卡。
  页面销毁后不继续读写。没有改动后台漫游策略、卡源、AT owner 或数据卡。
- 生产路径仍由既有 `sources/finish` 收录 common.js / roaming.js；没有新增服务、
  定时器或构建输入，也没有继续组装发行 ZIP。

## 验证

`tests/dashboard_roaming_scope.py` 在实际 Chromium 中执行生产公共模块和卡片，
RPC 全部模拟：覆盖慢速自动解析为 F50 逻辑栈 1、在途解析共用、正确保存卡号、
真实切卡阻止旧卡保存、过期读写响应、数据卡变化、未知卡、显式选卡及页面销毁。
原有 `dashboard_roaming.py` 的 18 组中／英／土耳其语、主题、布局、权限和加载／
错误场景，以及网络锁定按钮回归通过。测试没有访问设备或修改漫游开关。

本次只修改 Pro 仓库。U30 Pro 使用同一前端修复；本轮实机对象为 F50 Pro。
用户要求继续暂停打包，已经完成的 U30 Pro 模式／EN-DC ZIP 尚不含本次漫游修复，
不能作为此次问题已修复的交付件。

## 授权热部署与真实网页验证

用户明确允许热部署两个网页文件并仅做只读核对。部署前原文件备份在
`work/pro-roaming-scope-20261106/`，新文件逐一回读校验，HTTP 资源也与生产源码
逐字节一致。两张卡的漫游 enabled 前后均为 0，boot ID 和数据卡记录未改变。

使用全新 Chromium 会话打开实际 `admin/modem/locks` 页面并点击卡片的刷新按钮，
首次加载和刷新均读取逻辑栈 1，不再出现误报，开关正确显示关闭。验证器拦截并
禁止所有漫游 setter，实际记录只有 get，请求中没有 set；未点击漫游开关。
结果存于同一忽略目录，不作为构建输入。`sources/finish` 已更新固定生产根，
后续组包从仓库源码获取修复，不从实机或诊断目录复制。打包仍按用户要求暂停。
