# U30 Pro 电池与电量（2026-11-03）

第一阶段只改 U30 Pro 独立仓库；用户验收后再同步 MU300/E5。

网页入口为蜂窝 → 电池与电量：四张状态卡（电量、状态及电池净功率/电流/电压、所选区间电池使用时间、预估续航），下方百分比与放电功率曲线，最底部复用原充电管理。设备管理不再重复显示充电卡。沿用看板主题及中/英/土耳其语；手机为两列卡片，区间按钮折行。

复用原生 `u30pro-battlog` 与 `battery-log.uc`，保持 `u30pro.battery history` RPC 和 `/run/u30pro-battery/screen` 屏幕接口。10 秒采样、每分钟一条，保留十天；记录 `/etc/mu300/battery/battery.csv` 受当前更新/重装配置保留路径覆盖。只读 sysfs，不访问 AT、不校准 FGU、不改变充电策略。网页读取实时值，不等分钟桶。

预估只采用最近连续放电段：至少十分钟且有实际电量下降；充电、历史不足、电量不降、重启/缺失间隔均不估算，不用其他机型的电池容量硬套。关机空档留白，不连线、不计入在用时间。页面按浏览器本地时间标注日期及时间。

菜单依赖实际检测到的 Battery 类型及 present 状态生成标志，不硬编码产品名。硬件存在性改变时才清除 LuCI 菜单缓存。无电池不会启动采样服务；后续同步 MU300 时，F50/V50 也必须通过实际电池探测隐藏菜单。U30 Pro 实体屏幕直接消费同一份历史，不另起采集器；E5 实体屏幕本轮不做曲线。

正式组包在 `tools/u30pro-package.py` 注册服务、库及启动/停止链接；`tools/test-u30pro-root.py` 比对准备根与源码。native 改动在 adaptations.json 记录来源及当前摘要。无需重编内核或屏幕二进制。

离线验证：生产 ucode 与原生屏幕协议的九项测试（包括原生区间/能耗/屏幕/待落盘回归）；24 组实际浏览器页面与请求竞争测试；六组充电控制迁移回归；已核对源码来源、LMO 翻译、root 集成。浏览器截图使用合成数据，不能作为实机电池准确性或实际续航验收。

实机热部署已获用户明确授权。10 个文件回读摘要匹配；新增记录服务已启用，真实 CSV 与屏幕 16 行文件正常生成，认证后的网页四个时间区间和手机布局验证通过。整机 boot ID、AT 桥与基带加载器 PID 未改变，未写 NV/IMEI，未切卡或改变充电策略。实机截图在 out/battery-preview/live-desktop.png、live-mobile.png。长期电池趋势与续航估算仍需自然放电积累；充电时不显示估算值。
